# rust-dns

[![CI and Release](https://github.com/moliango/rust-dns/actions/workflows/release.yml/badge.svg)](https://github.com/moliango/rust-dns/actions/workflows/release.yml)
[![License: GPL-3.0](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](LICENSE)

**English** | [简体中文](README.zh-CN.md)

A Rust rewrite of the [mosdns](https://github.com/IrineSistiana/mosdns)-style DNS forwarder,
built for OpenWrt: plugin-style configuration, a seven-page LuCI UI, a local stats API, and a
Cloudflare IP optimizer.

> **Status:** the DNS core MVP and the management stack are implemented and tested: UDP/TCP
> listeners, `sequence` subset, UDP/TCP/DoT upstreams, TTL cache, stats events, seven LuCI pages,
> the OpenWrt service package and the Cloudflare optimizer.
> DoT/DoH/DoQ servers, DoH upstreams, IP_PKTINFO, multi-worker listeners, ECS/dual-stack
> preference and full geoip semantics are future work.

## Features

- **DNS forwarding core**
  - UDP/TCP listeners; `udp://`, `tcp://`, `tls://` (DoT) upstreams.
  - `sequence` subset: domain/IP matchers, hosts, redirect, allow/block/grey lists, reject,
    cache, response modifiers.
  - TTL cache (age-adjusted hits, lazy TTL, flush); query events feed `/api/v1`.
- **LuCI (7 pages)**
  - Basic, Rules, Geodata Update, Statistics, Logs, Cloudflare IP Optimizer, System Upgrade.
  - One-click MosDNS import, CodeMirror YAML editor, add/remove individual rule entries.
- **Local stats/admin API**
  - `/api/v1/{health,version,stats,history,top,logs,logs/clear,cache/flush}`; loopback only.
- **Cloudflare optimizer**
  - Latency + download probes, official range fetch/cache, `SO_MARK`/device binding,
    direct-egress verification.
  - Apply selected IPs to a managed `hosts.txt` block (atomic write, `.bak`, reload).
- **OpenWrt packaging**
  - `rust-dns` service package + `luci-app-rust-dns` frontend package, plus a
    bundled `geo2txt` helper for geodata updates.
  - Targets: OpenWrt 23.05+ (opkg), 24.10 (opkg), 25.12/main (apk).
  - Architectures: x86_64, aarch64, armv7 (no MIPS/armv5 in v1).

## Quick start

### 1. Release binary

Download `rust-dns-<version>-<arch>.tar.gz` from
[Releases](https://github.com/moliango/rust-dns/releases), extract it, then:

```sh
tar -xzf rust-dns-<version>-<arch>.tar.gz
cd rust-dns-<version>-<arch>
./rust-dns version
./rust-dns check -c /path/to/config.json
./rust-dns start -c /path/to/config.json -d /var/rust-dns

# in another terminal
dig @127.0.0.1 -p 5335 example.com
```

The config is normally generated by the OpenWrt service package's `config.sh` (below).

### 2. Build from source

```sh
rustup toolchain install 1.100.0
cd rust-dns
cargo test --workspace
cargo build --release
```

Static musl (aarch64 host example):

```sh
sudo apt-get install musl-tools
CC_aarch64_unknown_linux_musl=musl-gcc \
  cargo build --release --target aarch64-unknown-linux-musl
file target/aarch64-unknown-linux-musl/release/rust-dns   # statically linked
```

Cross-compilation via `cargo-zigbuild` (used by GitHub Actions):

```sh
cargo install cargo-zigbuild
cargo zigbuild --release --target aarch64-unknown-linux-musl -p rust-dns
cargo zigbuild --release --target armv7-unknown-linux-musleabihf -p rust-dns
```

### 3. OpenWrt packages

Detailed install guide (arch selection, opkg/apk, verify, troubleshooting):
[`docs/INSTALL-openwrt.md`](docs/INSTALL-openwrt.md).

Prebuilt packages are attached to each GitHub release by the CI workflow:

- **23.05.5 / 24.10.8 ipk**: x86_64, aarch64_generic, aarch64_cortex-a53,
  arm_cortex-a7_neon-vfpv4.
- **25.12.6 apk**: x86_64.

Each release ships four packages:

- `geo2txt` — geosite/geoip `.dat` unpacker used by the geodata updater.
- `rust-dns` — service/daemon package.
- `luci-app-rust-dns` — LuCI frontend.
- `luci-i18n-rust-dns-*` — optional Chinese UI translation.

Download the files matching your OpenWrt release and package architecture.
Release filenames are prefixed with the OpenWrt version and target arch to
avoid collisions, for example
`24.10.8_x86_64-24.10.8_rust-dns_0.1.2-r1_x86_64.ipk`. Install **geo2txt
first**, then the service package, then LuCI:

```sh
opkg install ./24.10.8_*_geo2txt_*.ipk
opkg install ./24.10.8_*_rust-dns_*.ipk
opkg install ./24.10.8_*_luci-app-rust-dns_*.ipk
# apk-based releases:
apk add --allow-untrusted ./25.12.6_*_geo2txt-*.apk
apk add --allow-untrusted ./25.12.6_*_rust-dns-*.apk
apk add --allow-untrusted ./25.12.6_*_luci-app-rust-dns-*.apk
```

Installing `geo2txt` first lets the local `rust-dns` package resolve it as a
dependency (`opkg`/`apk` do not resolve dependencies from local files).

Upgrades can also be run from LuCI: **Services → Rust DNS → System Upgrade** checks the
fixed `moliango/rust-dns` GitHub repository, selects only packages matching the
router's OpenWrt branch and target architecture, and verifies every download
against the release's `SHA256SUMS-packages` asset.

The `luci-i18n-rust-dns-*` package is optional (Chinese UI translation).

To build them yourself, place `openwrt/rust-dns`, `openwrt/geo2txt` and
`luci-app-rust-dns` under the OpenWrt SDK's `package/`, put the release tarball
SHA256 into `openwrt/rust-dns/hashes/<arch>.sha256`, then:

```sh
make package/geo2txt/compile V=s
make package/rust-dns/compile V=s
make package/luci-app-rust-dns/compile V=s
```

`rust-dns-<version>-openwrt-src.tar.gz` from the release can also be used as a local feed.

## Configuration model

On OpenWrt, UCI is the input; `/etc/init.d/rust-dns` runs `config.sh` to generate
`/var/etc/rust-dns/config.json`, and `rust-dns check` validates it before procd starts:

```text
/etc/config/rust-dns
        │ config.sh
        ▼
/var/etc/rust-dns/config.json  ── rust-dns check ──▶ procd start
        │
        ├─ udp_server / tcp_server → DNS listeners
        ├─ sequence → matcher / hosts / redirect / forward / cache
        ├─ forward → udp:// / tcp:// / tls:// upstreams
        └─ stats_collector → /api/v1
```

See `openwrt/rust-dns/files/rust-dns.config` and `config.sh` for the UCI fields,
defaults and generated JSON shape.

A `sequence` is an array of rule strings:

```json
"rules": [
  "hosts",
  "whitelist -> forward_local",
  "blocklist -> reject",
  "local-ptr -> reject",
  "ddnslist -> forward_local",
  "streaming -> forward_stream",
  "geosite_cn -> forward_local",
  "geoip_cn -> forward_local",
  "greylist -> forward_remote",
  "redirect",
  "modify_response",
  "cache",
  "forward_remote"
]
```

## LuCI pages

| Page | Contents |
|---|---|
| Basic | Listeners, logs, upstreams, cache, ECS/TTL, API, custom YAML |
| Rules | 8 rule files with add/remove entry |
| Geodata Update | geosite/geoip/adlist update, cron, proxy |
| Statistics | QPS, hit rate, top domains/clients, query log |
| Logs | Tail, level/keyword filter, clear |
| Cloudflare Optimizer | Probes, OpenClash bypass, results, write hosts |
| System Upgrade | Check GitHub Releases, verify SHA256, install ipk/apk, view log |

The LuCI package contains UI/rpcd only. `/etc/config/rust-dns`, rules, init and
`config.sh` are owned by the `rust-dns` service package.

## Stats / admin API

Default `127.0.0.1:9091`:

```sh
curl -s http://127.0.0.1:9091/api/v1/health
curl -s http://127.0.0.1:9091/api/v1/stats
curl -s 'http://127.0.0.1:9091/api/v1/logs?limit=20&offset=0&filter=all'
curl -s -X POST http://127.0.0.1:9091/api/v1/cache/flush
```

v1 only binds loopback; non-loopback addresses are rejected by `config.sh` and the CLI.

## Cloudflare optimizer

CLI:

```sh
rust-dns cf-optimize --source cloudflare --family 4 \
  --output /var/rust-dns/cf-optimizer/last.json \
  --progress /var/rust-dns/cf-optimizer/progress.json \
  --cancel-file /var/rust-dns/cf-optimizer/cancel
```

Write a managed hosts block (atomic, `.bak`, optional reload):

```sh
rust-dns cf-apply-hosts \
  --file /etc/rust-dns/rule/hosts.txt \
  --reload-init /etc/init.d/rust-dns \
  --entry cloudflare.com=104.16.0.1
```

The LuCI page wraps the same flow: parameters, live progress, sortable/filterable results,
per-row and bulk apply. OpenClash bypass is **best effort**: `--bypass-mode mark` uses
`SO_MARK` plus temporary `ip rule`/direct routes, `device` binds the WAN interface, and the
UI warns when direct-egress verification fails. Temporary rules are cleaned up on
finish/cancel/error.

## GitHub Actions

`.github/workflows/release.yml`:

- push/PR: `cargo fmt`, `clippy -D warnings`, `cargo test --workspace`, LuCI JS syntax,
  mock API and shell syntax.
- tag `v*` or manual dispatch: builds static musl binaries for x86_64/aarch64/armv7,
  produces `rust-dns-<version>-<arch>.tar.gz` + `.sha256`, and publishes a GitHub Release
  with `rust-dns-<version>-openwrt-src.tar.gz`.
- the same workflow builds OpenWrt ipk/apk packages with the OpenWrt SDK container
  (23.05.5/24.10.8 ipk for x86_64, aarch64_generic, aarch64_cortex-a53,
  arm_cortex-a7_neon-vfpv4; 25.12.6 apk for x86_64; plus the `geo2txt` helper)
  and attaches them to the release together with a `SHA256SUMS-packages`
  manifest used by the LuCI upgrade backend.
- Release:

```sh
git tag v0.1.2
git push origin v0.1.2
```

After publishing, copy the release SHA256 back into
`openwrt/rust-dns/hashes/<arch>.sha256` before building ipk/apk.

## Development and testing

```sh
cd rust-dns
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

LuCI / service package:

```sh
node --check luci-app-rust-dns/htdocs/luci-static/resources/view/rust-dns/*.js
python3 -m py_compile dev/mock-api/server.py
sh openwrt/rust-dns/tests/config_generator/run.sh
```

DNS core tests use in-process fake upstreams and ephemeral ports; they never touch the
external network or the system `dig`. The OpenWrt SDK, `ucode`, `shellcheck` and `msgfmt`
are not part of this environment; those checks run in CI or on a router.

## Limitations / roadmap

- Beyond the DNS core MVP: DoT/DoH/DoQ servers, DoH upstreams, IP_PKTINFO, multi-worker
  listeners, ECS/dual-stack preference and full geoip semantics are not implemented.
- Real-device installation on OpenWrt 23.05/24.10/25.12, LuCI rendering and ucode runtime
  validation still need CI/router coverage.
- OpenClash mark/device/pause modes need validation against a real OpenClash setup.
- MIPS/armv5 are out of v1 scope (Rust ships no prebuilt musl std).
