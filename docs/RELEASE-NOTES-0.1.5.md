# rust-dns 0.1.5 发布说明

修复 Cloudflare 优选“所有结果都是失败”的两个问题：候选 IP 只取自第一个网段，
以及没做下载测速的行也被标成失败。

## 一、根因

### 1. 候选只来自第一个 CIDR

`--source cloudflare` 拿到的是一组网段（`173.245.48.0/20`、
`103.21.244.0/22`、……、`104.16.0.0/13`、`172.64.0.0/13` 等）。旧代码按文档
顺序从每个 CIDR **从头展开**，凑够 `max_candidates` 就停：

```text
max_candidates = 1000
173.245.48.0/20 有 1024 个地址 -> 1000 个候选全部来自这一个 /20
后面的 104.16.0.0/13、172.64.0.0/13 等从未被测
```

Cloudflare 的不同网段在不同网络上的可达性差别很大。如果第一个 /20 在你的
线路（或代理规则下）不可达，结果就是 1000 行全部丢包、全部失败，而实际上
其他网段有可用 IP。实测同一台机器上，第一个 /20 全不通，而
`103.21.244.0/22`、`104.16.0.0/13` 等网段正常。

### 2. 未测速的行显示为“失败”

只有延迟前 `download_count`（默认 5）名会进入下载测速。其余行的
`speed_mbps` 为 0，而 `passed` 要求速度达到 `min_speed`，所以它们也显示
红色 “Failed”。1000 个候选里只有 5 个真正测了速度，看起来就像“全是失败”。

## 二、0.1.5 的修复

| # | 修复 |
|---|---|
| 1 | Cloudflare 网段改为**均匀采样**：把 `max_candidates` 平均分配到每个 CIDR，每个网段取等距中点，不再吃满第一个网段 |
| 2 | 采样跳过 IPv4 网络地址/广播地址（例如 `173.245.48.0`） |
| 3 | 结果 JSON 新增 `download_tested` 字段，标记该行是否进入过下载测速 |
| 4 | LuCI 结果表区分三态：**Passed** / **Failed**（测过但未达标）/ **Not tested**（延迟未进前 N，没测速度）；“Failed only” 过滤也只显示真正测过且失败的行 |
| 5 | 结果摘要增加 “Speed-tested: X / Passed: Y”，避免误解 |

`--source file` 仍按文件顺序展开，不改变用户显式给出的顺序。

## 三、升级到 0.1.5

```sh
cd /tmp
BASE=https://github.com/moliango/rust-dns/releases/download/v0.1.5
# 24.10.8 x86_64 示例，其他版本/架构替换前缀
wget "$BASE/24.10.8_x86_64-24.10.8_rust-dns_0.1.5-r1_x86_64.ipk"
wget "$BASE/24.10.8_x86_64-24.10.8_luci-app-rust-dns_0.1.5-r1_all.ipk"
opkg install ./24.10.8_x86_64-24.10.8_rust-dns_0.1.5-r1_x86_64.ipk
opkg install ./24.10.8_x86_64-24.10.8_luci-app-rust-dns_0.1.5-r1_all.ipk
```

25.12 / apk 用 `apk add --allow-untrusted` 安装对应的 `-0.1.5-r1.apk`。

升级后建议在优选页把 **Download tests** 适当调大（例如 10–20），让更多低延迟
IP 进入测速；表格里出现 **Not tested** 是正常现象，不代表失败。

如果使用 OpenClash 等透明代理，优选时请把 **Bypass mode** 设为 `mark`
（默认 mark `0x400000`），否则探测流量可能被代理接管，测到的不是直连质量。

## 四、验证

- 单元测试覆盖：3 个网段、上限 30 时各取 10 个；小上限也覆盖后续网段；
  等距采样跳过网络地址。
- 本机真实网络跑 60 个候选：候选分布在 20+ 个 /16，多个网段产生
  Passed 结果，而旧实现只会测 `173.245.48.0/20`。
- 结果 JSON 的 `results[]` 新增 `download_tested`；旧版 `last.json`
  仍可读取，缺失字段按未测速处理。

其余功能与 0.1.4 相同（0.1.4 修复了 Cloudflare 优选无法启动的
`fs.popen()` 兼容问题）。
